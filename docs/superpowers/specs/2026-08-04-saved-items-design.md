# 保存機能（履歴からの変更）設計仕様書

- 作成日: 2026-08-04
- 対象: shiboq
- 変更の要旨: 実行のたびに自動保存される「履歴」を、ユーザーが明示的に保存・削除する
  「保存」機能に変更する

## 背景と目的

現状は、jqクエリの実行が成功するたびに (JSON, クエリ, 結果) の組が
`~/.shiboq/history/` へ自動保存される。この方式には次の問題がある。

- jqは存在しないキーを参照してもエラーにならず `null` を返すため、`.a` → `.add` →
  `.address` のような入力途中の状態がほぼすべて「成功」として保存される。
  結果として一覧が意図しない項目で埋まる。
- 意図しない項目が増えるため200件で古いものから自動的に間引いているが、
  これは「ユーザーが残したかったもの」も消しうる。

そこで、保存を明示的な操作に変える。一覧に並ぶのは常にユーザー自身が選んだものだけになり、
自動間引きも不要になる。

## スコープ外

- 保存済み項目のリネーム（保存時に名前を付けられれば足りる。YAGNI）
- 保存済み項目の並べ替え・検索・タグ付け
- 保存済み項目のエクスポート／インポート

## バックエンド

### 永続化先の変更と移行

保存先を `~/.shiboq/history/` から `~/.shiboq/saved/` へ変更する。

起動時に「`saved/` が存在せず、かつ `history/` が存在する」場合に限り、
`os.Rename` でディレクトリごと移行する。移行は1回限りで、失敗しても
アプリの起動は継続する（保存先が空の状態で始まるだけで、致命的ではない）。
既存データを失わずに、ディレクトリ名を実態に合わせるための措置。

### 名称の変更

| 変更前 | 変更後 |
|---|---|
| `HistoryService` | `SavedService` |
| `HistoryEntry` | `SavedItem` |
| `SaveHistory` | `SaveItem` |
| `ListHistory` | `ListSaved` |
| `DeleteHistory` | `DeleteSaved` |
| `history_service.go` / `history_service_test.go` | `saved_service.go` / `saved_service_test.go` |

Wailsバインディング（`frontend/wailsjs/`）は `wails generate module` で再生成する。

### データ構造

```go
type SavedItem struct {
    ID        string    `json:"id"`
    Name      string    `json:"name"`
    JSON      string    `json:"json"`
    Query     string    `json:"query"`
    Result    string    `json:"result"`
    CreatedAt time.Time `json:"createdAt"`
}
```

`Name` を追加する。空文字を許容し、その場合は表示側で `Query` を代わりに使う。
移行してきた既存ファイルには `name` フィールドが無いが、`json.Unmarshal` では
ゼロ値（空文字）になるだけなので、追加の移行処理は不要。

### 挙動の変更

- **重複スキップを削除する。** 現在は直近の項目と (JSON, クエリ) が同一なら
  保存をスキップしているが、明示的な操作は押した通りに実行されるべきなので廃止する。
- **`pruneOldEntries` と `MaxEntries` を削除する。** ユーザーが意図して保存したものを
  黙って削除しない。`defaultMaxHistoryEntries` 定数と、間引きを検証するテストも削除する。

保持する挙動:

- 保存先は1件1ファイル（`{UUID}.json`）、ディレクトリ `0700`・ファイル `0600`
- 一時ファイル + `os.Rename` による原子的な書き込み
- 一覧は `CreatedAt` 降順（同時刻は ID 降順でタイブレーク）
- ID が空文字・UUID形式でないエントリは一覧から除外する
  （Svelte の `{#each ... (item.id)}` でキーが重複して例外になるのを防ぐため）
- `SaveItem` は ID 未指定なら UUID を発行し、`CreatedAt` 未設定なら現在時刻を入れる

## フロントエンド

### 保存ペイン（旧 履歴ペイン）

- 見出しを「履歴」から「保存」に変更する。
- ヘッダー右端に「＋ 保存」ボタンを置く。
- 各項目に、ホバーで現れる削除ボタン（×）を置く。
- 項目の表示は「名前（空なら `Query`）」と日時の2行。名前が長い場合は省略記号で切る。

### 保存の流れ

1. 「＋ 保存」ボタン、または `Ctrl+S` で名前入力ダイアログを開く。
2. 名前は空のままでも確定できる（プレースホルダに現在のクエリを表示）。
3. 確定すると、その時点の (名前, JSON, クエリ, 結果) を保存し、一覧を更新して
   保存した項目を選択状態にする。
4. `Esc` またはキャンセルで閉じる。

**現在の実行がエラー中は保存できない。** 表示されている結果は前回成功時のもので、
いま画面にあるJSON/クエリと対応しないため、保存すると内容が食い違う。
保存ボタンを無効化し、理由を `title` 属性で示す。`Ctrl+S` も同様に何もしない。

### 削除の流れ

1. 項目の × を押すと確認ダイアログを開く（参考プロジェクト sirusita と同じ形式）。
2. 確定すると削除し、一覧を更新する。
3. 削除したのが選択中の項目なら、選択を解除する（`selectedId` を `null` にする）。
4. `Esc` またはキャンセルで閉じる。

### 復元の流れ（変更なし）

項目をクリックすると (JSON, クエリ, 結果) をまとめて各ペインへ復元する。

### 削除される仕組み

自動保存が無くなることで、次が不要になる。

- `restoredSignature` / `signatureOf()` / `shouldSkipSave`
  （復元直後の内容を再保存しないための仕組み。以前これが単純な boolean だったために
  「復元後に編集した内容が保存されない」不具合を起こした箇所でもある）
- `evaluate()` 内の `SaveHistory` 呼び出しと、それに続く `refreshHistory()` 呼び出し

`evaluate()` は「スキーマ推論・使用キー抽出・クエリ実行」の3つだけを行うようになる。

**`evaluateToken` によるトークンガードは維持する。** `evaluate()` には依然として
複数の `await` があり、編集が重なれば複数の呼び出しが同時に飛行しうるため、
古い呼び出しが新しい結果を上書きする問題は残る。同様に `refreshSaved()`
（旧 `refreshHistory()`）の `savedRequestToken` によるガードも維持する。

## テスト

Go側（`saved_service_test.go`）に次を追加する。

- 同じ (JSON, クエリ) を続けて保存しても、2件とも保存される（重複スキップの廃止）
- 200件を超えて保存しても1件も間引かれない（自動間引きの廃止）
- `Name` が保存され、読み出しでも保持される
- `Name` が空のまま保存でき、読み出すと空文字になる
- 旧 `history/` ディレクトリからの移行: `history/` のみ存在する状態で移行を実行すると
  `saved/` に中身が移り、`history/` が無くなる
- 移行しない条件: `saved/` が既に存在する場合は `history/` を触らない

既存テストのうち、間引きと重複スキップを検証するものは削除する。それ以外
（CRUD・不正ID・並び順・パーミッション・原子的書き込み）は名称変更のうえ維持する。

フロントエンドはこれまでどおり自動テストを持たず、ビルドの成功と、
Xvfb 上で実アプリを起動しての目視確認で担保する。確認項目:

- 保存ボタンで名前入力ダイアログが開き、保存すると一覧に増える
- 名前を空で保存すると、一覧にクエリが表示される
- エラー中は保存ボタンが無効になる
- 削除の確認ダイアログが出て、確定すると一覧から消える
- 項目クリックでJSON・クエリ・結果が復元される
